# Shekati worldwide release localizations

The JSON files in `metadata/` contain product-page drafts, localized subscription display names and descriptions, and five screenshot headings in the order recorded in `locales.json`. The fields use Apple's [locale shortcodes](https://developer.apple.com/documentation/appstoreconnectapi/managing-metadata-in-your-app-by-using-locale-shortcodes), including `ar-SA` for an Arabic app bundle named `ar.lproj` and `no` for `nb.lproj`. The application picks the user's preferred app language. StoreKit supplies the purchase price and currency at runtime.

App translations start from the current English UI copy, the original Arabic dictionary, and the financial terms in the new flows. Translation drafts use a local MADLAD-400 model with manually supplied navigation, cheque lifecycle and metadata terms. The [CTranslate2 model revision](https://huggingface.co/Zoowr/madlad400-3b-mt-ct2-int8/tree/dc87a252892a42d835675f68543d574709d1d8f1) matches the downloaded binary's SHA-256 `2725586867e4ed59b2d16ecdfb58ed80086c9d60084572e64afd8765d62cac3f`. The model runs as a build tool outside the app. User cheques and photos never enter this translation workflow.

From the repository root, run `python Tools/Localization/audit_release.py` to check UI key parity, permission prompts, names, metadata lengths and screenshot-heading counts. Run `python Tools/Localization/audit_release.py --require-release` once screenshots and reviews are available. The latter also checks the evidence in `locales.json`: a linguistic pass, a native visual pass and the five capture paths for every store locale. Record only captures from the candidate binary and approval of the final copy.
